# Water Ford — refactor plan

Companion to `docs/dependency-audit.md` (read that first for the version facts).
Status: **plan** — nothing below has been executed yet.

## Goals

1. Make the mod **buildable and shippable** with the superproject tooling
   (`devctl mods build water-ford` — currently refuses this repo's layout).
2. Bring the repo in line with the superproject mod conventions
   (`mod/` portal-clean root, per-mod `AGENTS.md`, `dist/` output).
3. Hygiene refactor of the Lua **without touching the tile's visual config**
   — the piling/shadow architecture is the product of 13 documented experiment
   rounds (`docs/shadow-experiments.md`) and must be preserved byte-for-byte
   where it matters.

## Non-goals

- No gameplay changes (recipes, tech, balance stay as released in 1.0.0).
- No new graphics work. (There are no external art sources yet — graphics are
  generated by `tools/gen-placeholders.py`; `assets-src/` stays absent until
  real art exists.)
- No 2.0 release cut (optional follow-up; see audit §6.2).

## Phase 1 — layout: repo-root → `mod/`

Current deployable sits at the repo root; `devctl mods build` only accepts
`mod/` or `src/` layouts (repo-root is refused as "not portal-clean").

```
mods/water-ford/
  mod/                    NEW — the deployable, portal-clean at every commit
    info.json
    data.lua
    data-final-fixes.lua
    control.lua
    graphics/             (moved from root)
    locale/en/locale.cfg  (moved from root)
    changelog.txt         (moved from root)
    thumbnail.png         (moved from root)
  tools/gen-placeholders.py   stays (never shipped; standalone — depends only on
                              the dlc install path, which it already hardcodes)
  docs/                   stays (shadow-experiments.md + these two docs)
  AGENTS.md               NEW (see Phase 1b)
  README.md               NEW (build/dev notes, license pointer)
  LICENSE                 stays at root
  dist/                   build output (gitignored; root `*.zip` rule covers it)
```

Mechanics:

- `git mv` the deployable files into `mod/` (preserves history).
- `path-ignore` inside `graphics/…`/locale refs need no changes: `__water-ford__/`
  resolution is relative to the zip root, which becomes `mod/`'s content.
- `.gitignore`: root rule `*.zip` matches at any depth — keep as-is; it covers
  `dist/`.
- Verify: `devctl mods build water-ford` succeeds and the zip layout matches the
  current live folder layout (info.json at zip root).

## Phase 2 — code hygiene (behavior-preserving)

### 2a. data.lua — kill the extend-then-mutate pattern

Today: `data:extend(water_ford_item())` then, if py is loaded, mutate
`data.raw.recipe["water-ford"]` in place. That mutation subtlety already hid the
py recipe for three commits (see the file's own comment). Restructure so the bug
is structurally impossible:

```lua
local py_loaded = mods["pyalienlife"] ~= nil

local ingredients = py_loaded
    and { {type="item", name="treated-wood", amount=2}, … }   -- py branch
    or  { {type="item", name="wood", amount=4}, … }           -- vanilla branch

local prereq = py_loaded and {"creosote"} or {"concrete"}
```

— i.e. build the single final tables first, `data:extend` once. Keep the
comments explaining *why* the py ingredients are what they are (creosote-era
gating, gravel ballast), and add the provenance note from audit §5.

### 2b. i18n — make the locale file load-bearing

`locale/en/locale.cfg` defines `[item-name]`/`[item-description]`/
`[technology-name]`/`[technology-description]`, but every prototype overrides
with hardcoded English `localised_name`/`localised_description` — the locale
entries are currently dead and nothing is translatable.

- Remove the hardcoded `localised_*` from item, recipe-era strings, and
  technology in `data.lua`.
- The ford **tile** inherits water-shallow's localisation machinery: add
  `[tile-name]` / `[tile-description]` sections for `water-ford` to locale.cfg
  and drop the tile's hardcoded `localised_*` in data-final-fixes.lua.
- Watch for: the control-stage flying text is hardcoded English too — move it to
  locale (any custom section, e.g. `[water-ford-messages]`) or accept en-only
  for it; note the choice in AGENTS.md.

### 2c. data-final-fixes.lua — comments only

- Keep every semantic line of the tile config **identical** (variants, layer,
  collision_mask, transitions, effect).
- Add the audit's water-wube note (logo easter-egg tile, exists in 2.0+2.1 —
  not dead config) and the dependency-audit pointer next to the `pf` table.

### 2d. control.lua — no changes

The guard is correct and event-field usage is 2.0-safe (audit §3). Only the
optional flying-text localization from 2b applies.

## Phase 3 — verification

1. **Dump-diff regression** (strongest evidence the hygiene refactor is
   behavior-preserving): before starting, run `--dump-data` on the dlc install
   with a **pinned mod list** (base + space-age + water-ford + the py closure,
   exactly as linked today); after the refactor, run again with the same list
   and diff the JSON. Locale changes will show as localised-string shifts —
   everything else must be byte-identical.
2. **2.0 probe re-run**: repeat the audit's probe (info.json delta → dump on
   2.0.77, exit 0, tile intact) against the refactored tree.
3. **Build + smoke**: `devctl mods build water-ford`; relink
   (`devctl mods link water-ford dlc` if needed) and confirm the live folder
   shadows the zip; launch the dlc install and place/mine a ford once by hand.
4. `devctl repo selftest` is unaffected (no lib/ changes) but cheap to run
   after the pointer bump.

## Phase 4 — release

1. Version bump `1.0.0 → 1.0.1` in `mod/info.json` (patch: layout + i18n
   plumbing, no balance change); changelog entry.
2. Commit sequence (two-commit rule): work commits **inside the mod repo** →
   `devctl mods build` → GitHub Release with `dist/water-ford_1.0.1.zip` →
   portal upload → superproject pointer-bump commit.
3. Optionally open the `factorio-2.0` branch (audit §6.2) — separate decision.

## Risk register

| Risk | Mitigation |
|---|---|
| Tile refactor accidentally changes visuals | Phase 2c: tile config frozen; dump-diff (3.1) proves equality; hand visual check (3.3) |
| Locale switch breaks names in existing saves | Localised keys resolve at display time — old saves pick up locale names automatically; verify item/tech/tile names in-game during 3.3 |
| py recipe items drift (py suite reorganization) | Provenance documented in audit §5 + AGENTS.md; dump-diff with py enabled catches missing items at data stage |
| Zip layout regression (missing thumbnail/locale) | Build via devctl only; compare zip listing against pre-refactor layout |
